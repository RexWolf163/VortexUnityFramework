# Vortex Database System — Адаптер для Unity

**Версия:** 1.0  
**Платформа:** Unity (2021.3+)  
**Зависимости:**  
- Odin Inspector  
- Addressables  
- Vortex Core (внутренний фреймворк)

---

## 📌 Назначение

Адаптер предоставляет **типобезопасный, редакторно-дружественный интерфейс** к системе базы данных ядра Vortex, ориентированный на использование в Unity-приложениях. Он позволяет:

- Хранить данные приложения (предметы, способности, уровни и т.д.) в виде ScriptableObject-пресетов.
- Автоматически загружать их при старте через **Addressables**.
- Управлять ссылками на данные прямо в инспекторе с поддержкой поиска, фильтрации и валидации.
- Разделять записи на **глобальные (Singleton)** и **копируемые (MultiInstance)**.
- Интегрироваться с системой сохранения ядра без дополнительного кода.

---

## 🧱 Основные компоненты

### 🔹 `DatabaseDriver`
Основной адаптер, реализующий:
- `IDriver` — для подключения к ядру,
- `IProcess` — для участия в загрузке через `Loader`,
- `ISaveable` — неявно, через ядро.

Отвечает за:
- Загрузку пресетов через Addressables по заданным лейблам,
- Индексацию записей,
- Создание экземпляров записей по запросу.

### 🔹 `DbRecordAttribute`
Атрибут для полей в MonoBehaviour или ScriptableObject:

```csharp
[DbRecord(typeof(ItemRecord))]
public string ItemGuid;
```

Автоматически отображает dropdown со всеми подходящими записями в инспекторе (требуется Odin).

### 🔹 `RecordPreset<T>`
Базовый класс для создания пресетов:

```csharp
[CreateAssetMenu(menuName = "DB/Item")]
public class ItemPreset : RecordPreset<ItemRecord> { }
```

Поддерживает:
- Автоматическую генерацию GUID,
- Настройку типа записи (`Singleton` / `MultiInstance`),
- Отображение иконки и описания в инспекторе.

### 🔹 `DatabaseSettings`
Настройки адаптера: список лейблов Addressables, по которым загружаются данные.

---

## ⚙️ Настройка

1. Создайте настройки:
   ```csharp
   public class MyDatabaseSettings : DatabaseSettings { }
   ```

2. Убедитесь, что все ассеты базы данных:
   - Являются **Addressable**,
   - Помечены нужными лейблами в **Addressables Groups**.

3. В окне настроек приложения укажите **лейблы Addressables**, содержащие ваши пресеты (например, `"Database"`).

> ⚠️ Без корректных лейблов загрузка не состоится. Адаптер выдаст ошибку в консоль.

---

## 🖥 Редакторный UX

- При создании пресета автоматически генерируется уникальный GUID.
- При изменении имени — ассет переименовывается, предотвращая дубликаты.
- В полях с `[DbRecord]` отображается dropdown со списком записей, отфильтрованным по типу и режиму (`Singleton`/`MultiInstance`).
- Невалидные ссылки подсвечиваются красным.

---

## 🔄 Загрузка в рантайме

- Адаптер автоматически регистрируется в системе загрузки (`Loader`) при старте.
- Загрузка происходит **асинхронно в основном потоке**.
- После завершения вызывается событие `DatabaseDriver.OnInit`.

Получение данных:

```csharp
// Для Singleton-записей (ссылка на глобальный объект)
var item = Database.GetRecord<ItemRecord>(guid);

// Для MultiInstance (новая копия)
var itemCopy = Database.GetNewRecord<ItemRecord>(guid);
```

---

## 💾 Сохранение

Если запись реализует `GetDataForSave` / `LoadFromSaveData`, её состояние будет автоматически сохраняться и восстанавливаться через систему сохранения ядра. Адаптер не требует дополнительной настройки.

---

## ✅ Преимущества

- **Безопасность типов**: невозможно ошибиться с типом или режимом записи.
- **Стабильность в редакторе**: синхронная загрузка → мгновенная актуальность данных в инспекторе.
- **Гибкость**: поддержка локальных и remote-данных через Addressables.
- **Минимальный код**: управление данными — через инспектор, без boilerplate.
- **Интеграция**: работает с системами загрузки и сохранения ядра «из коробки».

---

## ⚠️ Ограничения

- Требуется ручная настройка лейблов в Addressables.
- Все записи должны быть `ScriptableObject`.
- Runtime-создание новых записей не поддерживается (только в редакторе).
