# `TimeController`

## Назначение
Центральный диспетчер для отложенного или аккумулированного вызова действий (`Action`) в Unity-приложении. Работает на основе UTC-времени, кэшируемого один раз за кадр.

## Контракт

### Вход
- `Call(Action action, float stepSecs = 0, object owner = null)`  
  Планирует выполнение `action` через `stepSecs` секунд.  
  - Если `owner == null` — вызов добавляется в FIFO-очередь без возможности отмены.  
  - Если `owner != null` — предыдущий вызов с тем же `owner` заменяется.  
  - Если `action == null` и `owner != null` — удаляется существующий вызов владельца.

- `Accumulate(Action action, object owner)`  
  Регистрирует `action` для владельца. Если вызывается несколько раз до конца кадра, выполняется только последний.  
  Выполнение происходит автоматически в `LateUpdate`, если очередь непуста.

- `RemoveCall(object owner)`  
  Удаляет отложенный вызов и аккумулированное действие для `owner`.

### Выход
- Вызов зарегистрированных `Action` в момент наступления запланированного времени или в конце кадра (для аккумулированных действий).
- Исключения внутри `Action` логируются через `Debug.LogError`, но не прерывают выполнение других действий.

### Гарантии
- Анонимные вызовы (`owner == null`) выполняются в порядке добавления (FIFO).
- Для одного `owner` активен только последний вызов.
- Порядок выполнения между разными владельцами **не гарантируется**.
- Время (`TimeController.Time`) округляется до двух знаков после запятой.
- Все операции выполняются в main thread (Unity `LateUpdate`).

### Ограничения
- Не поддерживает отмену анонимных вызовов.
- Точность выполнения ограничена шагом проверки (`0.1` секунды).
- Не предназначен для высокоточных временных задач (например, аудио- или сетевой синхронизации).
- Использование из других потоков приводит к неопределённому поведению.

## Внутренняя организация

### Структуры данных
- `_anonymousQueue: List<QueuedAction>` — для вызовов без владельца. Поддерживает FIFO.
- `_queue: Dictionary<object, QueuedAction>` — для вызовов с владельцем. Гарантирует один активный вызов на владельца.
- `NextWaveQueue: Dictionary<object, Action>` — для аккумулированных действий.

### Производительность
- Проверка очередей происходит не чаще чем раз в `0.1` секунды.
- Перед полной проверкой выполняется быстрая проверка по `_nextTimer` (минимальное время следующего события).
- При отсутствии готовых таймеров сканирование очередей не происходит.
- Используется переиспользуемый буфер `ReadyQueue` для минимизации аллокаций.
- Аккумулированные действия выполняются автоматически в `LateUpdate`, если очередь не пуста.

## Инициализация
Создаётся автоматически при старте сцены через `[RuntimeInitializeOnLoadMethod]`. Объект помечается как `DontDestroyOnLoad`. Ручная инициализация не требуется.
