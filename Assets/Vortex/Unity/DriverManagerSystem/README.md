# Vortex Driver Manager

**Версия:** 1.0  
**Платформа:** Unity 2021.3+  
**Зависимости:**  
- Odin Inspector  
- Vortex Core (`SystemController`, `ISystemDriver`, `IProcess` и др.)

---

## 📌 Назначение

Пакет **Vortex Driver Manager** предоставляет механизм централизованной конфигурации и валидации соответствия между **системами ядра** (например, `AudioProvider`, `Database`, `SaveController`) и их **платформо-зависимыми драйверами** (например, `AudioDriver`, `DatabaseDriver`, `SaveSystemDriver`).

Он реализует **явную, типобезопасную привязку драйверов без использования DI-контейнеров**, что соответствует архитектурной парадигме статической, синглтон-ориентированной модели.

---

## 🔧 Основные компоненты

### 1. `DriverConfig` — настроечный ассет
- ScriptableObject, помеченный интерфейсом `ICoreAsset`.
- Содержит таблицу соответствий: **Система → Драйвер**.
- Поддерживает **валидацию**: запрещает сохранение, если не все драйверы назначены.
- Автоматически создаётся в `Assets/Resources/` при первом запуске или через меню `Vortex/Debug/Check Core Assets` с остальными `ICoreAsset`.

### 2. `DriversGenericList.cs` — автогенерируемый белый список
- C#-файл, расположенный в корне пакета.
- Содержит статический словарь `WhiteList`, сопоставляющий:
  - `AssemblyQualifiedName` системы ядра → `AssemblyQualifiedName` разрешённого драйвера.
- Генерируется **автоматически** при нажатии кнопки **«Reload»** или **«Save Config»** в инспекторе `DriverConfig`.
- Используется в `SystemController<T, TD>.SetDriver()` для **строгой проверки совместимости**.

### 3. Редакторный UX
- В инспекторе `DriverConfig` отображается таблица всех систем, реализующих `ISystemController`.
- Для каждой строки — выпадающий список доступных драйверов (реализаций `IDriver` из сборок `ru.vortex.*`).
- При загрузке проекта:
  - Проверяется наличие `DriversGenericList.cs`.
  - Если файл отсутствует или не соответствует текущему `DriverConfig` — выводится предупреждение в консоль.

## ⚙️ Настройка

1. Убедитесь, что в проекте установлен **Odin Inspector**.
2. Откройте `Assets/Resources/DriverConfig.asset` (создаётся автоматически).
3. Назначьте драйвер для каждой системы через выпадающие списки.
4. Нажмите **«Save Config»** — будет обновлён файл `DriversGenericList.cs`.
5. Запустите приложение — драйверы подключатся автоматически через `RuntimeInitializeOnLoadMethod`.

> ⚠️ **Важно**: после изменения конфигурации **обязательно сохраняйте** через кнопку **«Save Config»**, иначе изменения не вступят в силу.

---

## 🔒 Безопасность и надёжность

- **Типобезопасность**: невозможно подключить несовместимый драйвер — проверка происходит на этапе вызова `SetDriver()`.
- **Раннее выявление ошибок**: отсутствие драйвера или несоответствие конфигурации приводит к логированию ошибки ещё до запуска основной логики.
- **Защита от ручного вмешательства**: файл `DriversGenericList.cs` помечен как автогенерируемый — его редактирование вручную не рекомендуется.

---

## ⚠️ Ограничения

- **Не поддерживает DLL-дистрибуцию**: поскольку `DriversGenericList.cs` генерируется в исходниках, пакет нельзя скомпилировать в `.dll`.
- **Требует перегенерации при добавлении новых систем**: после создания новой системы ядра нужно нажать **«Reload»** в `DriverConfig`.

---

## 🛠 Пример использования

1. Создаёте новую систему:
   ```csharp
   public class MyService : SystemController<MyService, IDriver> { ... }
   ```
   Создаёте драйвер:
   ```csharp
   public class MyServiceDriver : IDriver { ... }
   ```
   Открываете DriverConfig → нажимаете «Reload» → выбираете MyServiceDriver для MyService.
   Нажимаете «Save Config».
   При старте приложения:
   ```csharp
   // Внутри MyServiceDriver.Register():
   MyService.SetDriver(Instance); // ✅ проходит проверку
   ```

📝 Примечание: Пакет является неотъемлемой частью фреймворка Vortex и требует соответствующих зависимостей.
