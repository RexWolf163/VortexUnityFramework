# Mapped Parameters — техническая документация

**Версия**: 1.0  
**Назначение**: Реализация иерархических систем параметров в среде Unity с конфигурацией на уровне редактора и минимальным вмешательством в исходный код.  
**Требования**: Unity 2021.3 или новее, Odin Inspector (для расширенного отображения в инспекторе), C# 8+.  
**Область применения**: Настройка зависимостей между игровыми характеристиками (например, «Сила» → «Урон в ближнем бою») в рамках редакторной фазы разработки.

---

## 1. Архитектурный обзор

Пакет **Mapped Parameters** реализует паттерн *иерархического параметрического графа*, где узлы представляют собой параметры, а направленные рёбра — зависимости с ассоциированной стоимостью. Система разделена на две логические части:

- **Редакторная подсистема**: конфигурирование структуры графа через ScriptableObject (`ParametersMap`), валидация корректности связей, экспорт визуального представления.
- **Runtime-подсистема**: загрузка и использование структуры параметров в игровой логике через наследование от `MappedParametersGroup<T>`.

Все компоненты размещены в неймспейсе `Core.MappedParameters`.

---

## 2. Основные компоненты

### 2.1. `ParametersMap` (ScriptableObject)

Центральный элемент системы. Хранит:

- **Базовые параметры** (`baseParams: string[]`) — корневые узлы графа, не имеющие родителей.
- **Производные параметры** (`mappedParams: MappedParameterPreset[]`) — узлы с указанием одного или нескольких родителей и стоимости связи.

#### Редакторные функции:
- Автоматическая проверка уникальности имён параметров.
- Обнаружение и прерывание циклических зависимостей.
- Удаление ссылок на несуществующие родительские параметры.
- Кнопка **Sort**, реализующая топологическую сортировку по иерархии.
- Динамическое обновление выпадающих списков при изменении структуры.

### 2.2. `MappedParameterPreset`

Описывает один производный параметр:

- `Name`: строковый идентификатор.
- `Parents`: массив объектов `MappedParameterLink`.
- `CostLogic`: справочное поле типа `MappedParameterParentCostLogic` (`And`, `Or`, `Sum`), предназначенное исключительно для семантической аннотации в редакторе.

### 2.3. `MappedParameterLink`

Определяет однонаправленную связь с родителем:

- `Parent`: строковое имя родительского параметра.
- `Cost`: целочисленное значение ≥1. Интерпретация зависит от пользовательской логики (стоимость улучшения, порог активации, весовой коэффициент и т.п.).

### 2.4. `GenericParameter`

Runtime-представление параметра:

```csharp
public class GenericParameter
{
    public string Name { get; internal set; }
    public int Value { get; internal set; }
    public void SetValue(int value);
}
```

### 2.5. `MappedParametersGroup<T>`

Абстрактный базовый класс для runtime-группы параметров:

```csharp
public abstract class MappedParametersGroup<T> : IMappedParametersGroup
    where T : ParametersMap
```

#### Публичные методы:
| Метод | Сигнатура | Назначение |
|------|-----------|-----------|
| `Init()` | `void` | Инициализирует внутреннее состояние, загружает `ParametersMap` из `Resources`. |
| `GetValue(string)` | `int` | Возвращает текущее значение параметра по имени. |
| `GetParents(GenericParameter)` | `GenericParameter[]` | Возвращает массив родительских параметров. |
| `GetCost(string)` | `MappedParameterLink[]` | Возвращает массив связей (родитель + стоимость). |

> **Примечание**: Загрузка осуществляется через `Resources.LoadAll<T>("")`. Поддерживается только один экземпляр `T` в `Resources`.

### 2.6. `MappedParameterAttribute` и `MappedParameterAttributeDrawer`

Атрибут для декларативного связывания строкового поля с доступными параметрами:

```csharp
[MappedParameter(typeof(MyStatsGroup))]
public string selectedParameter;
```

Drawer автоматически формирует выпадающий список на основе `GetParametersList()`, вызываемого у указанной группы.

## 3. Редакторные утилиты

### 3.1. Валидация

При любом изменении `ParametersMap` выполняется комплексная проверка:

1. Уникальность имён (автоматическое переименование дубликатов: `Param_1`, `Param_2`).
2. Существование всех родительских параметров.
3. Отсутствие циклов в графе зависимостей.

Ошибки регистрируются через `Debug.LogError` с префиксом ⚠️.

### 3.2. Экспорт графа

Меню: **Vortex → Debug → Export Mapped Parameters into Graph**  
Формат: **DOT (Graphviz)**  
Онлайн визуализатор: https://dreampuf.github.io/GraphvizOnline
Файл сохраняется с расширением `.dot` и содержит:

- Узлы базовых параметров (выделены цветом `#b3e5fc`).
- Узлы производных параметров.
- Рёбра с метками стоимости.

Пример фрагмента:
```dot
"Strength" -> "MeleeDamage" [label="5"];
```

## 4. Инструкция по применению

### Шаг 1. Создание карты параметров
1. Создать ScriptableObject типа `ParametersMap`.
2. Заполнить `baseParams` и `mappedParams` через инспектор.

### Шаг 2. Реализация runtime-группы
```csharp
public class CharacterStats : MappedParametersGroup<CharacterParametersMap>
{
    private void Awake()
    {
        Init(); // обязательный вызов
    }
}
```

### Шаг 3. Использование в компонентах
```csharp
public class UpgradeSystem : MonoBehaviour
{
    [MappedParameter(typeof(CharacterStats))]
    public string targetParameter; // ← dropdown со всеми параметрами
}
```

### Шаг 4. Реализация игровой логики
Интерпретация поля `Cost` и применение значений параметров остаётся на усмотрение разработчика.

---

## 5. Ограничения и замечания

1. **Тип значения**: Все параметры хранят значение как `int`. Расширение типов требует модификации `GenericParameter`.
2. **Зависимость от Odin Inspector**: Без этой библиотеки атрибут `MappedParameter` не предоставляет функциональности выбора из списка.
3. **Хранение данных**: Используется папка `Resources`, что не рекомендуется для крупных проектов. Для масштабирования требуется кастомный механизм загрузки.
4. **Редакторная область применения**: Структура графа не предназначена для изменения в рантайме. Возможна только модификация значений через `SetValue`.

---

## 6. Заключение

Пакет **Mapped Parameters** обеспечивает строгую, типобезопасную и визуально контролируемую систему конфигурирования иерархических параметров. Он минимизирует необходимость написания boilerplate-кода для управления зависимостями и переносит ответственность за корректность структуры на этап редакторной настройки, что соответствует принципам *fail-fast* и *data-driven design*.
