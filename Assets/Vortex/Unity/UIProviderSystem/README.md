# Vortex UI Provider System

Управление жизненным циклом пользовательских интерфейсов на основе декларативных условий и централизованной шины данных.

## Назначение

### Решает
- Регистрация и управление состоянием (открыто/закрыто) интерфейсов через единую шину `UIProvider`
- Автоматическое открытие/закрытие интерфейсов по заданным условиям (`UserInterfaceCondition`)
- Сохранение позиции перетаскиваемых окон между сессиями
- Предотвращение конфликтов состояний через декларативные условия

### Не решает
- Верстку и визуальное оформление интерфейсов
- Логику обработки пользовательского ввода внутри интерфейса
- Управление переходами между сценами
- Анимацию открытия/закрытия (делегируется внешним твинерам)

## Зависимости

| Тип | Компонент |
|-----|-----------|
| Ядро фреймворка | `Vortex.Core.DatabaseSystem`, `Vortex.Core.SaveSystem`, `Vortex.Core.AppSystem` |
| Платформа | `UnityEngine.UI`, `Vortex.Unity.UI.Tweeners` (опционально) |

## Ключевые концепции

| Концепция | Описание | Пример |
|-----------|----------|--------|
| **Тип интерфейса** | Классификация для фильтрации в методах шины | `Common` — базовые окна (меню); `Panel`/`Overlay`/`Popup` — вторичные элементы |
| **Условие** | Логика, определяющая необходимость открытия/закрытия | `SaveLoadStartCondition` — показывает индикатор при загрузке/сохранении |
| **Автоматизация** | Интерфейс сам управляет своим состоянием через условия | Настроенный `UserInterface` открывается без вызова `UIProvider.Open()` |
| **Позиция окна** | Смещение относительно якоря, сохраняется между сессиями | Перетащил окно → позиция сохранена → при следующем запуске окно на том же месте |

## ⚠️ Критические требования

1. **Не требуется наследование компонента `UserInterface`**  
   Все различия между интерфейсами задаются через пресет `UserInterfacePreset` (ScriptableObject). Компонент `UserInterface` используется «как есть» — достаточно указать нужный пресет в поле `preset`. Расширение функционала происходит через:
   - Выбор типа интерфейса (`UIType`) в пресете
   - Набор условий (`Conditions`) в пресете
   - Связывание с перетаскиваемой зоной (`UIDragHandler`) и контейнером окна на сцене

2. **Уникальность GUID пресета**  
   Каждый `UserInterfacePreset` должен иметь уникальный `GuidPreset`. Дубликаты приведут к перезаписи данных в индексе шины `UIProvider` и непредсказуемому поведению.

3. **Обязательная регистрация**  
   Интерфейс должен быть зарегистрирован через `UIProvider.Register(id)` до первого использования. Регистрация обычно происходит автоматически компонентом `UserInterface` при активации (`OnEnable`), но требует:
   - Корректного указания `preset` (GUID пресета)
   - Завершения инициализации `Database` (событие `Database.OnInit`)

4. **Инициализация условий**  
   Каждое условие (`UserInterfaceCondition`) должно вызвать `Init(data, callback)` в своём методе `Run()`. Без инициализации условие не будет отслеживать изменения состояния и не повлияет на поведение интерфейса. При реализации условия **обязательно** вызывайте `RunCallback()` для немедленной проверки при инициализации.

5. **Типизация интерфейсов**  
   Тип `UIType` (`Common`, `Panel`, `Overlay`, `Popup`) влияет только на поведение методов шины:
   - `UIProvider.CloseAll()` закрывает только интерфейсы типа `Common`
   - `UIProvider.GetOpenedUIs()` возвращает только открытые `Common`-интерфейсы  
   Для реализации автоматического закрытия при открытии другого интерфейса необходимо явно добавить условие `CloseOnOpenAnyUICondition` в пресет.

6. **Перетаскивание окон**  
   Для работы перетаскивания (`UIDragHandler`) обязателен `CanvasScaler` в родительской иерархии. При его отсутствии перетаскивание отключается с логированием ошибки.

## Контракт

### Вход
- `UserInterfacePreset` в папке `Resources` с заполненными полями:
  - `GuidPreset` — уникальный идентификатор
  - `Conditions` — массив условий открытия/закрытия
  - `UIType` — тип интерфейса (`Common`, `Panel`, `Overlay`, `Popup`)
- `UserInterface` компонент на объекте сцены с указанием `preset` (GUID пресета)

### Выход
- Автоматическое управление видимостью интерфейса через условия
- Сохранение позиции перетаскиваемых окон между сессиями
- События `OnOpen`/`OnClose` для реакции на изменение состояния

### Гарантии
- Состояние интерфейса (`IsOpen`) всегда синхронизировано с визуальным представлением
- Позиция окна сохраняется только для интерфейсов с подключённым `UIDragHandler`
- Условия проверяются при изменении их внутреннего состояния и при регистрации интерфейса

### Ограничения
- Не поддерживает вложенность условий (условие не может зависеть от состояния другого интерфейса напрямую)
- Перетаскивание работает только с `CanvasScaler` в родительской иерархии
- Позиция окна сохраняется в локальном пространстве (`localPosition`), а не в мировом

## Кодогенерация

### Генератор условий интерфейсов

Система предоставляет инструмент ускорения разработки через контекстное меню редактора:

| Инструмент | Путь в меню | Назначение |
|------------|-------------|------------|
| `UI Condition Generator` | `Assets/Create/Vortex/UI Condition` | Генерация шаблона наследника `UnityUserInterfaceCondition` с заготовленной структурой методов `Run()`, `DeInit()`, `Check()` |

### Принцип работы генератора

1. Создаёт шаблон класса с правильной структурой наследования от `UnityUserInterfaceCondition`
2. Автоматически добавляет обязательные методы:
   - `protected override void Run()` — запуск отслеживания состояния
   - `public override void DeInit()` — остановка отслеживания
   - `public override ConditionAnswer Check()` — логика проверки условия
3. Добавляет комментарии-заглушки с пояснением назначения каждого метода

### Важные ограничения

- Сгенерированный код **требует ручной доработки**:
  - Реализация логики в методе `Check()`
  - Подписка/отписка на события в `Run()`/`DeInit()`
  - **Обязательный вызов `RunCallback()` в `Run()`** для немедленной проверки при инициализации
- Генератор работает **только в редакторе** и не влияет на рантайм
- Сгенерированный код не содержит бизнес-логики — только структурную основу

### Пример использования генератора

1. Выберите папку в окне Project
2. ПКМ → `Create` → `Vortex` → `UI Condition`
3. В появившемся файле реализуйте логику:

```csharp
public sealed class MyCustomCondition : UnityUserInterfaceCondition
{
    protected override void Run()
    {
        // Подписка на события
        SomeSystem.OnEvent += RunCallback;
        RunCallback(); // ⚠️ Обязательный вызов для немедленной проверки!
    }

    public override void DeInit()
    {
        // Отписка от событий
        SomeSystem.OnEvent -= RunCallback;
    }

    public override ConditionAnswer Check()
    {
        // Логика проверки
        return SomeSystem.IsActive ? ConditionAnswer.Open : ConditionAnswer.Close;
    }
}
```

> 💡 **Рекомендация**: Используйте генератор как отправную точку. Всегда проверяйте сгенерированный код на соответствие архитектурным требованиям проекта.

## API Reference

### UIProvider (шина)
```csharp
// Регистрация интерфейса в шине (обычно вызывается из UserInterface)
UserInterfaceData ui = UIProvider.Register("guid_here");

// Ручное управление состоянием
UIProvider.Open("guid_here");
UIProvider.Close("guid_here");
UIProvider.CloseAll(); // закрывает все Common-интерфейсы

// Проверка состояния
bool hasOpen = UIProvider.HasOpenedUIs();
UserInterfaceData[] list = UIProvider.GetOpenedUIs();
```

### UserInterfaceData (модель)
```csharp
// События изменения состояния
ui.OnOpen += () => { /* окно открыто */ };
ui.OnClose += () => { /* окно закрыто */ };

// Доступ к данным
bool isOpen = ui.IsOpen;
(int x, int y) offset = ui.Offset; // позиция окна
```

### UserInterfaceCondition (абстракция условия)
```csharp
// Обязательные методы для реализации
protected abstract void Run();    // запуск отслеживания состояния
public abstract void DeInit();   // остановка отслеживания
public abstract ConditionAnswer Check(); // проверка условия
```

## Использование

### 1. Создание интерфейса с автоматическим управлением

1. Создайте `UserInterfacePreset` через меню `Create > Database > UserInterface Preset`
2. Настройте параметры:
   - Укажите `UIType = Common` для базового меню
   - Добавьте условие `AutoLoadCondition` для автоматической загрузки при старте
3. Создайте объект на сцене с компонентами:
   - `UserInterface` → укажите `preset` (выберите через выпадающий список)
   - `CanvasGroup` или `Tweener*` → для анимации открытия/закрытия
4. При запуске приложения интерфейс автоматически откроется

### 2. Интерфейс с перетаскиванием

```csharp
// На объекте окна:
// 1. Добавьте компоненты:
//    - RectTransform (контейнер окна)
//    - UIDragHandler (зона перетаскивания, обычно панель заголовка)
//    - UserInterface (указать preset)
// 2. Свяжите компоненты:
[SerializeField] private UIDragHandler dragZone;
[SerializeField] private RectTransform wndContainer;

// В UserInterface автоматически настроена связь:
// dragZone.OnDrag += (delta) => wndContainer.anchoredPosition += delta;
```

Позиция окна сохраняется автоматически через `SaveSystem` при выходе из приложения.

### 3. Условие: закрытие при открытии любого меню

```csharp
/// <summary>
/// Условие: Закрывать если открывается любой другой интерфейс того же типа (по умолчанию — Common)
/// </summary>
public sealed class CloseOnOpenAnyUICondition : UnityUserInterfaceCondition
{
    protected override void Run()
    {
        UIProvider.OnOpen += RunCallback;
        RunCallback(); // Немедленная проверка при инициализации условия
    }

    public override void DeInit()
    {
        UIProvider.OnOpen -= RunCallback;
    }

    public override ConditionAnswer Check()
    {
        var list = UIProvider.GetOpenedUIs();
        // Если открыт хотя бы один другой интерфейс (не текущий) — закрыть
        if (list.Length > 0 && (!list.Contains(Data) || list.Length > 1))
            return ConditionAnswer.Close;
        return ConditionAnswer.Idle;
    }
}
```

### 4. Ручное управление через кнопку

```csharp
// На кнопке:
[SerializeField] private CallUIHandler handler;
// В инспекторе укажите:
//   - uiId: GUID пресета интерфейса
//   - closeUI: false (открыть) / true (закрыть)

// Или программно:
UIProvider.Open("settings_menu_guid");
```

## Граничные случаи

| Ситуация | Поведение |
|----------|-----------|
| Попытка открыть уже открытый интерфейс | Игнорируется, событие `OnOpen` не вызывается |
| Попытка закрыть уже закрытый интерфейс | Игнорируется, событие `OnClose` не вызывается |
| Условие возвращает `Open`, когда интерфейс уже открыт | Состояние не изменяется, триггеры не вызываются |
| Отсутствие `CanvasScaler` при перетаскивании | Перетаскивание отключено, логируется ошибка |
| Несколько условий возвращают противоречивые ответы | Приоритет у `Close` над `Open` |
| Интерфейс деактивирован до `DeInit()` | Условия автоматически отписываются в `OnDisable` |
| Вызов `RunCallback()` пропущен в `Run()` | Условие не проверит текущее состояние при инициализации → возможны ошибки логики |
