# `LoaderSystem` — Система загрузки приложения

**Версия:** 1.0  
**Платформа:** .NET Standard 2.1+ (независимо от Unity)  
**Уровень архитектуры:** 1 (`Vortex.Core.LoaderSystem`)  
**Зависимости:**  
- Vortex Core (`App`, `Settings`, `Log`, `IProcess`)  
- `System.Threading.Tasks`

---

## Назначение

Пакет `LoaderSystem` реализует **централизованную, асинхронную систему загрузки компонентов приложения**, управляемых через интерфейс `IProcess`.  
Он обеспечивает:

- Регистрацию компонентов до старта загрузки,
- Автоматическое упорядочивание по зависимостям (`WaitingFor()`),
- Интеграцию с жизненным циклом приложения (`AppStates`),
- Поддержку отмены и прогресса загрузки.

Система не содержит логики инициализации самих компонентов — только оркестрацию их запуска.

---

## Контракт

### Вход
- **`Loader.Register(IProcess process)`** — регистрация компонента в очереди загрузки.
- **`Loader.Run()`** — запуск процесса загрузки.
- **`IProcess.WaitingFor()`** — метод, возвращающий типы компонентов, которые должны быть загружены до текущего.

### Выход
- Все зарегистрированные компоненты вызывают `RunAsync(CancellationToken)`.
- События: `OnLoad`, `OnComplete`, `GetCurrentLoadingData()`, `GetProgress()`, `GetSize()`.

### Гарантии
- Загрузка происходит **один раз** за сессию (`_isRunning`).
- Порядок загрузки **полностью определяется зависимостями**.
- При наличии циклической зависимости система **аварийно завершает приложение** с логированием ошибки.
- Компоненты, не указанные в `DriversGenericList`, **не могут быть зарегистрированы как драйверы**, но могут участвовать в загрузке как `IProcess`.

### Ограничения
- **Нет поддержки параллельной загрузки** независимых компонентов — всё выполняется строго последовательно.
- **Отмена загрузки не откатывает состояние** уже загруженных компонентов.
- **Повторная регистрация одного и того же типа** игнорируется, но **разные экземпляры одного типа** могут быть зарегистрированы.

---

## Поведение в граничных случаях

| Сценарий | Поведение |
|---------|----------|
| Циклическая зависимость (`A → B → A`) | Логирование `"Cyclic dependency detected!"`, вызов `App.Exit()` |
| Зависимость от несуществующего типа (`WaitingFor()` возвращает `typeof(NonExistent)`) | Логирование ошибки; если ни один контроллер не может быть загружен — трактуется как цикл |
| Отмена токена во время загрузки | Прерывание без отката; состояние `App` остаётся `Starting` |
| Повторный вызов `Loader.Run()` | Игнорируется (`_isRunning = true`) |

---

## Архитектурные требования

- Любой компонент, участвующий в загрузке, **должен реализовывать `IProcess`**.
- Регистрация **должна происходить до вызова `Loader.Run()`**, обычно в `RuntimeInitializeOnLoadMethod` драйвера.
- Компоненты **не должны полагаться на порядок подписки** — только на `WaitingFor()`.

> ⚠️ **Важно**: `Loader.Run()` вызывается **внешним триггером** (например, `LoaderStarter` в Unity), а не автоматически.

---

## Пример использования

```csharp
// В драйвере (уровень 2)
[RuntimeInitializeOnLoadMethod]
private static void Register()
{
    if (MyService.SetDriver(Instance))
        Loader.Register(Instance); // Instance реализует IProcess
}

// Реализация IProcess
public Type[] WaitingFor() => new[] { typeof(Database), typeof(Localization) };
public async Task RunAsync(CancellationToken token)
{
    // Инициализация после Database и Localization
}
```

## Интеграция с Unity

Служба `LoaderSystem` находится на уровне ядра и содержит только логику загрузки сервисов.
Команду к запуску загрузки нужно давать снаружи, например через компонент `LoaderStarter` (MonoBehaviour, подписывается на `App.OnStarting`),
- `LoaderView` (визуализация прогресса).

Эти компоненты находятся в пакете `Vortex.Unity.Components.LoaderSystem`.
