# Vortex — Минималистичный, защищённый и предсказуемый фреймворк для Unity

**Версия:** 1.0  
**Платформа:** Unity 2021.3+ (.NET Standard 2.1+)  
**Зависимости:** Odin Inspector  

---

## 🌀 Философия и основные принципы

> **«Минимальная, защищённая, предсказуемая архитектура, где каждая строчка кода оправдана практической пользой»**

Vortex строится на трёх китах:

### 1. Программирование как управление данными

Любая задача решается через **чёткий цикл из трёх этапов**:

- **Получение данных** — из шины (`Database.GetRecord<T>(guid)`) или внешнего источника.
- **Отображение данных** — визуализация через UI, звук, анимации, VFX.
- **Обработка рефлексии** — реакция на действия пользователя и события окружения.

> **Важно:** Рефлексия обрабатывается **после отображения**, так как пользователь реагирует именно на то, что видит.  
> Изменение глобального состояния происходит **только в контроллере**, **никогда** — в UI или модели.

### 2. Технологии только по делу

Любой инструмент (DI, синглтоны, интерфейсы, паттерны) вводится **только если он даёт измеримую пользу**:  
— упрощает поддержку,  
— ускоряет разработку,  
— предоставляет уникальные возможности.  

В противном случае — он **избыточен и опасен**.

### 3. Защита от деградации архитектуры

Главная угроза — **неконтролируемые изменения, смешение слоёв, потеря защиты ключевых компонентов**.  
Vortex обеспечивает:

- Чёткое разделение ответственности между уровнями.
- Запрет на `new T()` для управляемых типов.
- Статическую, типобезопасную привязку драйверов без DI-контейнеров.
- Единую точку принятия решений — **контроллер**.

## 🧱 Архитектура: Четырёхуровневая модель

| Уровень | Назначение | Примеры |
|--------|------------|---------|
| **1. Ядро фреймворка** | Платформонезависимая логика на чистом C# (.NET Standard). Максимально абстрактная, доменно-нейтральная. | `Record`, `SystemModel`, `ISaveable`, `App`, `Loader` |
| **2. Адаптация ядра к движку** | Платформозависимая, но доменно-нейтральная логика. Реализует универсальный паттерн под Unity. Может использоваться в любом Unity-проекте. | `DatabaseDriver`, `AudioDriver`, `UIProvider`, `DriversGenericList` |
| **3. Ядро приложения** | Доменно-специфичная, но переиспользуемая логика внутри семейства продуктов. | `PlayerStatsController`, `ConfiguratorController` |
| **4. Частные скрипты** | Уникальная, проектно-специфичная логика. Не переносится без модификации. | Сценарий миссии, UI главного меню |

> **Правило ссылок:** Верхние уровни могут ссылаться на нижние. Обратное — **запрещено**.  
> **Namespace-соответствие:** `Vortex.Core` → уровень 1, `Vortex.Unity` → уровень 2.

## 🔑 Ключевые компоненты

### `Database` — шина данных
- Централизованное хранилище Singleton- и MultiInstance-записей.
- Глобальный доступ через статические методы:  
  `GetRecord<T>(guid)` — ссылка на существующую запись,  
  `GetNewRecord<T>(guid)` — новая копия пресета.
- Интеграция с системой сохранения **только для Singleton-записей**.
- MultiInstance-записи **не сохраняются** — их жизненный цикл управляется потребителем.

### `SystemController<T, TD>` — основа всех систем
- Управление жизненным циклом через драйверы **без DI-контейнеров**.
- Типобезопасная привязка через автогенерируемый белый список (`DriversGenericList.cs`).
- Единый механизм инициализации и уничтожения.

### `Loader` — система загрузки
- Регистрация модулей через `IProcess`.
- Автоматическое выстраивание порядка загрузки по зависимостям.
- Поддержка прогресса и отладки.

### `TimeController` — централизованный таймер
- Отложенные и аккумулированные вызовы действий.
- Защита от дублирования через владельца (`owner`).
- Выполнение в `LateUpdate` с шагом проверки 0.1 сек.

### `UIProvider` — управление интерфейсами
- Регистрация UI через `UserInterfaceData` (наследник `Record`).
- Поддержка условий открытия/закрытия через `UserInterfaceCondition`.
- События `OnOpen` / `OnClose`.

### `LogicChains` — визуально конфигурируемые цепочки логики
- Этапы → действия → условия → переходы.
- Полностью описывается в `ScriptableObject`.
- Поддержка асинхронных условий (ожидание загрузки сцены и т.п.).

### `MappedParameters` — иерархические параметры
- Описание связей между параметрами через `ParametersMap`.
- Поддержка стоимости развития, зависимостей и логики проверки (`And`/`Or`/`Sum`).
- Автоматическая генерация графа зависимостей.

## ⚙️ Интеграция

1. Установите **Odin Inspector**.
2. Создайте `DriverConfig.asset` в `Assets/Resources/` (автоматически или через `Vortex/Debug/Check Core Assets`).
3. Назначьте драйверы для всех систем через инспектор.
4. Нажмите **«Save Config»** — сгенерируется `DriversGenericList.cs`.
5. Запустите приложение — всё подключится автоматически.

> ⚠️ После добавления новой системы — нажмите **«Reload»** в `DriverConfig`.

## 🛡️ Безопасность и надёжность

- **Раннее выявление ошибок**: отсутствие драйвера или несоответствие конфигурации логируется до запуска основной логики.
- **Типобезопасность**: невозможно подключить несовместимый драйвер.
- **Защита от деградации**:  
  — запрет на `new T()` для управляемых типов,  
  — строгая инкапсуляция логики изменений в контроллерах,  
  — единая точка принятия решений.
- **Статическая архитектура**: предсказуемое поведение, минимум side effects.

---

## ⚠️ Ограничения

- **MultiInstance-записи не сохраняются** — только Singleton.
- **Нет подписки на изменения** в `Database`.
- **Одно изолированное состояние базы данных** на приложение.
- **Не поддерживает DLL-дистрибуцию** из-за автогенерируемого `DriversGenericList.cs`.
